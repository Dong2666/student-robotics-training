# Daily Report — 2026-09-26

## Today's Goal

Milestone 2.4: publisher/subscriber communication inside
student_robotics.

## Completed

- status_publisher node: publishes `status <n> uptime=<s>` on /status
  at 1 Hz via a timer callback (sequence + elapsed time in every
  message)
- status_subscriber node: logs every received message
- Both registered in entry_points; std_msgs added to package.xml;
  package version 0.2.0
- Verified with CLI tools: ros2 topic hz measured 1.002/0.999 Hz,
  echo showed sequence and uptime incrementing together, node/topic
  list confirmed the graph, subscriber received consecutive messages
  (evidence in docs/ros2_communication_tests.md)
- Both nodes exit with code 0 on SIGINT — clean-shutdown criterion
  met
- docs/ros2_communication_tests.md (5 manual tests) and a README
  pub/sub section

## Problems Encountered

- Stale build cache: after adding entry points, the generated scripts
  existed but the installed entry-point metadata was old
  (StopIteration at runtime). Deleting build/install/log and
  rebuilding clean fixed it — rebuild and re-source after entry-point
  changes is mandatory
- SIGINT during spin raised ExternalShutdownException (not
  KeyboardInterrupt), leaving a traceback on exit; catching both
  exceptions makes the shutdown clean
- Testing pitfall: `ros2 run` is a wrapper process — killing the
  wrapper does not signal the node; Ctrl+C works because the terminal
  signals the whole foreground process group

## What I Learned

- ros2 topic hz/echo turn "looks fine" into measured evidence
- After entry_points changes: clean rebuild + re-source, or runtime
  discovery breaks while the build itself looks fine
- rclpy shutdown can surface as ExternalShutdownException; handle it
  for a clean exit
- Process groups matter: signal a ros2 run tree via its group, the
  way Ctrl+C does
